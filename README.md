# 로스트아크 골드 장부
## 신뢰도 수수료 (v1.3.0)

판매 금액은 상대에게 보내는 골드입니다. 거래마다 신뢰도 충분/없음/일부 보유를 선택하며, 일부 보유는 거래 직전 신뢰도를 만 단위로 입력합니다. 게임 신뢰도를 자동 조회하거나 잔여 신뢰도를 추적하지 않습니다. 다른 계정을 선택하거나 판매를 마치면 신뢰도 입력은 초기화됩니다.

- 추가 수수료 = max(0, 판매 골드 − 거래 직전 신뢰도) × 25%.
- 보유액/다음 주 이월에서는 판매액+수수료를 차감하고, 목표에서는 판매액만 차감합니다.
- 수령자 5%는 별개이며 판매자 보유액에서 다시 차감하지 않습니다. 아이템 계산기의 수수료 추정 설정과도 별개입니다.
- 공식 공지에 소수 골드 반올림 규칙이 명시되지 않아 1 G 미만은 올림 추정하며, 펼침 메뉴에서 게임에 표시된 실제 추가 수수료를 정수 G로 입력할 수 있습니다.
- 내역 금액 편집 시 당시 신뢰도로 재계산합니다. 직접 지정한 수수료는 편집창에서 함께 확인/수정하세요. 기존 기록은 수수료 0으로 유지합니다.
- JSON에는 수수료가 포함됩니다. 시트 전송은 기존 다섯 열 호환을 위해 별도 `신뢰도 수수료` 음수 행을 보냅니다. 시트 스크립트 자체는 변경하지 않았습니다.

조사 근거: [2025-07-23 공식 업데이트](https://lostark.game.onstove.com/News/Notice/Views/13173), 2026-10-14 확인. 신뢰도는 계정 단위이며 성장 활동의 일반 골드 소비는 1:1, 귀속 골드는 10% 획득으로 안내됩니다. 우편 회수/반송 후 골드 수령 시 소모 신뢰도가 복구되지만 이 장부는 실제 게임 신뢰도 잔액을 관리하지 않습니다.

검증: `node scripts/test-trust.cjs`는 실제 앱 함수를 추출해 계산/등록/수정/이월을 검증합니다. 전체 브라우저 테스트는 `scripts/test-ledger.cjs`에 추가했습니다.

개인 데이터를 제외한 단일 HTML 배포본. 현재 소스 버전 **1.3.1**. 실제 배포 버전은 사이트 하단에서 확인하세요.

아이템 계산기는 기본적으로 수수료 차감 전 예상 가치를 표시합니다. 수수료 추정 비율을 직접 설정하면 현금 환산·부족액·필요 수량에 반영합니다. 거래별 반올림/최소 수수료는 미반영입니다. 혼합 계획 계산은 실제 보유 기록을 변경하지 않습니다. 기존 가격은 직접 입력 모드로 보존됩니다. 지원 아이템의 자동 시세를 사용하려면 행에서 가격 방식을 자동 시세로 선택하세요. 계산기의 마지막 입력 변경 또는 삭제는 실행 취소할 수 있으며, 이 취소 기록은 새로고침 시 초기화됩니다.

주간 장부는 판매 전 잔액/목표 미리보기와 최근 5단계 실행 취소를 제공합니다. 주간 취소 기록은 새로고침 후에도 유지되며, 현재 주차 변경만 대상으로 합니다. 판매 금액은 양수이고 해당 계정의 현재 보유액 이하여야 합니다. 내역 편집·삭제로 음수 잔액을 만드는 것도 방지합니다. 과거에 저장된 음수 기록은 임의 변경하지 않습니다.

여러 탭 저장은 Web Locks와 저장 내용 비교로 보호합니다. 오래된 탭의 입력은 거부하고 최신 기록을 불러오므로 안내를 확인한 뒤 다시 입력하세요. 다른 탭의 미저장 입력을 병합하지는 않습니다. 업데이트 후 열어둔 이전 버전 탭도 모두 새로고침해야 보호가 적용됩니다.

## 코드와 데이터
- Git 관리: HTML, 버전, 변경 기록, 검사 스크립트.
- Git 제외: 실제 계정명·사진, 주간 기록, 판매 내역, 카드값, 현금, API 키, 시트 주소, JSON/CSV 백업, 화면 캡처.
- 입력 데이터는 브라우저 localStorage(`lag_` 접두사)에 저장됩니다. Git은 이 데이터를 백업하거나 복원하지 않습니다.
- 기존 브라우저 저장 영역에서 열면 기록이 보일 수 있지만 HTML에 그 기록이 포함된 것은 아닙니다.
- 배포본은 사진 없이 시작합니다. 데이터 메뉴에서 개인 사진 전용 JSON을 복원하면 브라우저에 저장되고 이후 JSON 백업에 포함됩니다. 개인 사진과 복원 파일은 GitHub에 올리지 않습니다. 목표·아이템 가격은 0, 환율 1,000원은 예시이므로 설정이 필요합니다.
- 외부 글꼴을 사용합니다. API 키와 시트 주소를 설정하면 해당 서비스로 통신합니다.

## 실행과 업데이트
GitHub Pages의 HTTPS 주소를 최신 Chrome/Edge에서 엽니다. 빈 프로필에서는 일반 계정 4개와 기록 없는 장부로 시작합니다. Web Locks가 없는 환경에서는 안전을 위해 저장을 차단합니다.

1. 사용 중인 장부에서 JSON 백업을 내려받아 **저장소 밖**에 보관합니다.
2. 코드 변경 후 VERSION, HTML application-version, CHANGELOG.md를 함께 갱신합니다.
3. `node scripts/check-release.cjs`로 검사합니다.
4. 필요한 파일만 스테이징하고 `git diff --cached`로 직접 검토한 뒤 커밋합니다.
5. 예: `git tag -a v1.1.0 -m "v1.1.0"`.
6. 원격 연결 후 선택한 브랜치와 태그만 업로드합니다.

실제 사용 중인 HTML은 아직 교체하지 않았습니다. 업데이트 시 백업 후 동일 경로와 브라우저를 유지하세요. 다만 file: URL의 저장소 동작은 브라우저마다 다르므로 데이터 유지 여부를 확인해야 합니다. 경로·브라우저·호스트 변경 시 JSON 가져오기가 필요할 수 있습니다. API 키는 백업에서 제외되므로 재입력이 필요할 수 있습니다.

가져오기는 계정·아이템·설정 및 같은 주차를 덮어쓰며, 파일에 없는 주차·사진은 유지합니다. 가져오기 전 형식과 건수를 확인하고 저장 중 오류가 나면 이전 값을 복구합니다(브라우저 강제 종료까지 보장하는 데이터베이스 트랜잭션은 아닙니다). API 키·시트 연결은 해당 브라우저의 기존 설정을 유지합니다. 새 기기에서는 직접 연결해야 합니다. 백업 요청 시각은 다운로드 완료를 보장하지 않으므로 파일을 확인하세요.

## 회귀 테스트

`scripts/test-ledger.cjs`는 Playwright/Chromium이 설치된 환경에서 `node scripts/test-ledger.cjs`로 실행합니다. 별도 런타임은 `LEDGER_PLAYWRIGHT`(모듈 위치), `LEDGER_BROWSER`(브라우저 실행 파일) 환경 변수로 지정할 수 있습니다. `LEDGER_SCREENSHOT_DIR`를 지정하면 테스트 화면을 그 폴더에 저장합니다. 해당 폴더는 저장소 밖을 사용하세요.

모든 기록은 임시 브라우저 컨텍스트의 가상 데이터이며 외부 통신은 차단합니다. 시세 API는 모의 응답으로 검증합니다. 테스트는 탭 충돌, 판매 검증, 실행 취소, 백업/복구, 수수료/혼합 계획, 반응형/키보드, 저장 실패, 주차 이월을 포함합니다. GitHub Actions의 현재 기본 검사는 문법·버전·개인정보 패턴 검사이며, 브라우저 회귀 테스트는 릴리스 전 별도로 실행합니다. 5회차 후기와 반영 내역은 [REVIEW-CYCLES.md](REVIEW-CYCLES.md)에 있습니다.

롤백은 원하는 태그의 HTML을 별도 폴더에 추출해 검사한 뒤 적용합니다. Git 롤백으로 브라우저 데이터까지 되돌아가지는 않습니다. 데이터 형식 변경이 있는 릴리스는 이전 코드와 호환되는지 먼저 확인하세요.

검사 스크립트는 임베디드 이미지, 흔한 토큰·서비스 주소 패턴, 기본값, 의도하지 않은 추적 파일을 검사합니다. 모든 개인정보를 탐지하지는 못하므로 변경 내용 직접 검토도 필요합니다.

## 자동 배포
최초 한 번 Settings → Pages → Source를 GitHub Actions로 설정해야 합니다.
이후 main 업로드 → 버전·문법·개인정보 패턴 검사 → 사이트 배포 → 실제 HTML 일치 확인 순서로 실행됩니다.
검사에 실패하면 배포하지 않습니다. PR은 검사만 수행하며 사이트에는 배포하지 않습니다.
배포에는 index.html과 VERSION만 포함되며 개인 백업·사진은 포함되지 않습니다.
별도 장기 토큰이나 Actions Secret 없이 GitHub의 작업용 토큰을 사용합니다.
Actions → Validate and deploy ledger → Run workflow로 main을 수동 재배포할 수도 있습니다.
실패 내역은 Actions 실행 결과에서 확인하세요. 자동 롤백은 수행하지 않습니다.

### 에이전트의 기본 배포 경로: 인증된 Git 업로드

2026-10-15 사용자 실행 권한 변경 후 에이전트 환경에서 기존 Git Credential Manager 인증과 브라우저 테스트가 정상 실행됐습니다. 기본 경로는 검사 → 커밋/버전 태그 → atomic push → GitHub Actions → 실제 HTML 검증입니다. 사용자에게 매번 CMD 실행을 요청하지 않습니다. 인증은 기존 보안 저장소를 사용하며 토큰을 소스나 로그에 기록하지 않습니다.

배포 전 원격 main과 로컬 기준 커밋을 비교하고, 변경 내역·개인정보 검사 및 회귀 테스트를 확인합니다. 릴리스 커밋과 태그가 일치하는지 검사한 뒤 main과 해당 태그만 `git push --atomic`으로 함께 전송합니다. force push는 사용하지 않습니다. 업로드 성공만으로 배포 완료를 선언하지 말고 Actions 결과와 `node scripts/verify-live.cjs`의 실제 HTML 해시 일치를 확인합니다.

인증이나 실행 권한이 바뀌면 다시 제한될 수 있습니다. Windows 권한 오류, 인증 저장소 오류, GitHub 권한 오류를 구분하고 동일한 실패를 반복 시도하지 않습니다. 보안 설정 변경은 사용자 승인 없이 수행하지 않습니다.

### 대안: 승인된 GitHub 연결

Git 업로드가 불가능하고 GitHub 연결의 실제 쓰기 작업이 허용된 경우 다음 API 경로를 사용할 수 있습니다. 저장소 쓰기 권한만으로 도구 실행 승인까지 보장되지는 않습니다. 연결이 만료·해제되면 재승인이 필요합니다. 이 대안은 v1.3.1 배포에 사용한 경로가 아닙니다.

1. 원격 main 커밋과 로컬 기준 커밋이 일치하는지 확인합니다. 다르면 먼저 변경사항을 검토하며 강제로 덮어쓰지 않습니다.
2. 버전·변경 기록 갱신 후 개인정보/구문 검사와 변경 범위에 맞는 테스트를 실행합니다.
3. 원격 main의 기존 트리를 base_tree로 지정해 검토된 변경 파일만 포함한 트리와 단일 커밋을 만듭니다. 삭제는 명시적으로 승인된 파일만 대상으로 합니다.
4. main을 갱신할 때 expected_sha에 확인한 기존 커밋을 지정하고 force=false를 사용합니다. 충돌 시 최신 상태를 다시 확인합니다.
5. main 변경으로 기존 GitHub Actions 검증·배포가 실행됩니다. 해당 커밋의 작업 결과와 실제 사이트 HTML 해시를 확인해야 완료로 보고합니다.
6. 원격 커밋을 로컬로 가져옵니다. 로컬 작업 파일이 업로드 내용과 같은지 확인하고 동일한 트리를 스테이징한 후 fast-forward로 맞춥니다. 작업 파일을 강제 초기화하지 않습니다.

GitHub API로 만든 커밋은 로컬에서 별도 커밋을 만들어 중복하지 않습니다. 연결 도구에 태그 생성 기능이 없으면 버전 파일과 커밋 SHA를 릴리스 식별자로 사용하고, 원격 태그가 만들어졌다고 주장하지 않습니다. 로컬 push용 CMD는 예비 경로이며 새 버전의 원격 태그 유무를 먼저 확인해야 합니다.

이 경로에서도 업로드 승인 범위는 현재 사용자의 요청을 따릅니다. 편집할 때마다 무조건 자동으로 공개하는 백그라운드 작업은 설치하지 않습니다. 배포 파일은 index.html과 VERSION뿐이며 브라우저 개인 기록은 포함하지 않습니다.
